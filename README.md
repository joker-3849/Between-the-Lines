# Between the Lines

Сайт книжного клуба: полка прочитанных книг, карточка каждой книги
с мнениями всех участниц, страница цитат, хроника встреч и лонгрид с итогами года.

На полке — двенадцать реальных встреч клуба с апреля 2024 по май 2026:
оценки по пяти критериям, ответы «Перечитаешь?» и отзывы участниц перенесены
из записей встреч как есть.

Статический сайт без сборки: HTML, CSS и ES-модули. Все данные — два JSON-файла
в репозитории.

## Запуск

Браузер не отдаёт JSON по `file://`, поэтому нужен любой локальный сервер:

```bash
python3 -m http.server 8000
# затем открыть http://localhost:8000
```

Для публикации подойдёт GitHub Pages: Settings → Pages → Deploy from a branch,
корень репозитория.

## Данные

### `data/club.json`

Участницы, критерии оценки, шкала, ближайшая встреча.

```jsonc
{
  "cadenceDays": 14,             // шаг между встречами
  "nextMeeting": "2026-09-11",   // если дата в прошлом, она сама катится вперёд
  "currentlyReading": { "title": "…", "author": "…" },
  "members":  [{ "id": "katya", "name": "Катя", "initial": "К",
                 "color": "#d9a94c", "g": "f" }],
  "criteria": [                  // по ним и только по ним ставятся баллы
    // short — короткая подпись для осей радара, где полное название не влезает
    { "id": "plot",       "label": "Сюжет и структура",              "short": "Сюжет" },
    { "id": "characters", "label": "Персонажи",                      "short": "Персонажи" },
    { "id": "style",      "label": "Ясность и выразительность языка", "short": "Язык" },
    { "id": "themes",     "label": "Тематика и идеи",                "short": "Идеи" },
    { "id": "emotion",    "label": "Эмоциональное воздействие",      "short": "Эмоции" }
  ],
  "yearHighlights": { "2025": { "lineOfTheYear": { "bookId": "…", "memberId": "…" } } }
}
```

`g` — род («f» / «m»), нужен для подписей вроде «предложила Лиза» и «самый строгий».
Добавить участника — добавить объект в `members`; все шкалы, фильтры и итоги
подхватят его автоматически. То же с критериями: список в `criteria` — источник
правды, и форма правки, и шкалы на карточке строятся прямо по нему.

**Среднего балла в данных нет.** Он всегда считается из выставленных критериев:
средний балл участника — среднее его оценок, средний балл книги — среднее по
участникам. Поэтому он не может разойтись с критериями после правки.

### `data/books.json`

Одна книга — один объект. Мнение каждой участницы лежит в `reviews`:

```jsonc
{
  "id": "norvezhskiy-les",
  "title": "Норвежский лес", "author": "Харуки Мураками",
  "year": 1987, "pages": null, "genre": "Роман",
  "edition": "",
  "art": {                       // своя обложка, пока нет фотографии настоящей
    "bg": "#16301f",             // фон
    "fg": "#e7f2e5",             // текст
    "acc": "#9ec96f",            // цвет рисунка
    "motif": "rain"              // сам рисунок, см. ниже
  },
  "discussed": "2025-12-18",     // дата встречи
  "proposedBy": null,
  "coverQuery": "Норвежский лес Харуки Мураками",
  "cover": null,                 // выходные данные издания; сайт их не рисует
  "isbn": null,                  // ISBN издания — сайт его не показывает
  "reviews": {
    "tanya": {
      "scores": {                // ключи — id критериев из club.json
        "plot": 8, "characters": 8, "style": 9,
        "themes": 8, "emotion": 10
      },
      "reread": true,            // «Перечитаешь?»: true / false / null
      "text": "Впечатление в свободной форме.",
      "line": { "text": "Своя формулировка с обсуждения." },
      "quote": { "text": "Цитата прямо из книги." }
    }
  }
}
```

* `year`, `pages`, `edition` и `isbn` можно не заполнять (`null` / `""`) —
  это скажется только на рекордах в «Итогах года»: карточки «Самая толстая»
  и «Самая старая» показываются, лишь когда есть на чём их посчитать.
* `scores` может быть заполнен частично — среднее считается по тому, что есть.
* `reread` — `true` (да), `false` (нет) или `null`, если человек не ответил;
  в блоке «Перечитаешь?» показываются только ответившие.
* `quote` — цитата прямо из книги, `line` — своя формулировка с обсуждения
  («Между строк»). Это два независимых поля, любое можно оставить `null`.
* Всё, что дальше, считается само: средний балл, разброс, книга года, самый
  строгий критик, статистика жанров.

## Обложки

Обложки у клуба свои: сайт рисует их из поля `art` — цвет фона, цвет текста,
акцент и геометрический мотив. Никаких фотографий настоящих изданий не
показывается, и никакие картинки со стороны не запрашиваются.

Раньше в панели над полкой был переключатель «свои / настоящие», а
фотографии брались с Open Library по `isbn`. Сервис по нашим книгам ничего
не отдаёт, так что переключатель, подсказка под ним, скрипт
`tools/fetch-covers.mjs` и весь код загрузки внешних картинок убраны —
вместе с настройками читателя (`assets/js/settings.js`), где эта пара
режимов была единственным пунктом.

Поля `cover`, `coverRemote` и `isbn` в `data/books.json` остаются просто
выходными данными издания: сайт их не рисует. Если фотографии когда-нибудь
понадобятся, вернуть путь загрузки будет несложно — но с источником,
который отвечает.

### Рисунок на обложке

У каждой книги своя палитра и мотив — простая геометрия, отсылающая
к содержанию. Мотивы живут в `assets/js/covers.js`, добавить новый — дописать
функцию в объект `MOTIFS` (сетка 200×300, цвет берётся из `var(--acc)`).

| `motif` | что рисует | где сейчас |
|---|---|---|
| `moon` | полная луна и рамка вокруг | Мастер и Маргарита |
| `rain` | дождь между стволами | Норвежский лес |
| `deco` | веер ар-деко из угла | Убийство Роджера Экройда |
| `zone` | свечение над обочиной | Пикник на обочине |
| `frame` | картина в раме | Щегол |
| `veil` | молочная белизна | Слепота |
| `orbit` | орбиты вокруг точки | Краткая история времени |
| `regency` | двойная рамка с ромбом | Гордость и предубеждение |
| `sun` | зной, лучи из угла | Сто лет одиночества |
| `water` | круги по воде | Все, чего я не сказала |
| `planet` | планета с кольцом и звёзды | Автостопом по галактике |
| `grid` | стеклянная сетка | Мы |

`"motif": null` — обложка останется просто цветной, без рисунка.

## Добавить книгу

Кнопка «Добавить книгу» в панели над полкой открывает форму: название и автор обязательны,
остальное — по желанию, включая мнения участниц, которые разворачиваются по одной.

Сайт статический и читает полку из файла в репозитории, поэтому форма не
пишет в `data/books.json` сама:

1. Книга сразу появляется на полке и открывается её страница — так виднее,
   получилось ли то, что нужно. Это черновик, который живёт только в памяти
   текущей вкладки: обновите страницу — и он пропадёт.
2. На странице черновика есть кнопка «Показать JSON для вставки» — она
   собирает объект книги в точности в формате `books.json`.
3. Скопируйте его (кнопка справляется сама, а если браузер не даёт доступ
   к буферу обмена — текст уже выделен, остаётся Ctrl/Cmd+C) и вставьте
   отдельным элементом в массив в `data/books.json`.
4. Закоммитьте.

Мнение участника попадает в экспорт, только если для него заполнено хоть
что-то — пустые карточки в `reviews` не создаются.

## Поделиться

Кнопка **«Поделиться»** рядом с «Внести изменения» открывает карусель
карточек 9:16 — формат сторис. Под каждой кнопка «Скачать», которая отдаёт
настоящий PNG 1080×1920.

Карточки собираются под книгу: нет выписанных строчек — не будет карточки
с цитатой, не заполнено впечатление — не будет карточки с ним.

| Карточка | Что на ней |
|---|---|
| **Обложка** | Жанр, название, автор, крупный средний балл, дата обсуждения. Фон — палитра книги из поля `art`. |
| **Цитата** | Выписанная строчка крупным шрифтом, имя автора строчки, под ней книга и балл. По одной карточке на каждую строчку, максимум три. |
| **Впечатление** | Отзыв целиком — по отдельной карточке на каждого участника. Кегль подбирается под длину текста, так что короткое впечатление читается крупно, а длинное всё равно помещается без обрезки. |
| **Оценки** | Средний балл каждой участницы с полосой и бейджем «перечитает» / «не перечитает», внизу средний балл клуба. |
| **Профиль** | Тот же радар-пятиугольник, что на карточке книги: клуб залитой фигурой, участницы контурами. |

Всё рисуется на `canvas` (`assets/js/sharecards.js`), а не вёрсткой: только
так получается файл, который можно скачать и выложить. Размеры внутри кода
всегда в координатах 1080×1920 — контекст масштабируется перед отрисовкой,
поэтому один и тот же код даёт и превью в окне, и полноразмерный файл.

Внизу каждой карточки — тот же логотип, что в шапке сайта: антиква,
«the» курсивом и приглушённым цветом. На canvas он собирается из трёх
кусков вручную (`wordmark()`), потому что рисовать можно только одним
шрифтом за раз.

Две тонкости:

* Canvas берёт шрифты из документа, но только уже загруженные, поэтому перед
  первой отрисовкой ждём `ensureFonts()` — иначе заголовки и логотип уедут
  в подстановочный шрифт.
* Скачивание идёт двумя путями. На обычном сайте — обычной ссылкой
  `<a download>` с blob. В предпросмотре артефакта Claude страница не может
  скачивать файлы сама, поэтому там используется `claude.use("downloads")`;
  код сначала пробует его и молча откатывается на ссылку, если механизма нет.

Добавить карточку — дописать функцию рисования и строчку в `cardsFor()`.

## Кто может править

По умолчанию сайт — обычная страница для чтения: полка, карточки книг,
разделы. Ни «Добавить книгу», ни «Внести изменения» не показываются вовсе.

Правки открывает кнопка **«Редактор»** в шапке справа. По клику она
спрашивает фразу клуба; назвали верно — появляются добавление книги, правка
карточек, удаление и сохранение. Вход запоминается в этом браузере
(`localStorage` хранит хеш), так что переспрашивают один раз.

Сама фраза при этом лежит в `sessionStorage` — она нужна как ключ к токену
сохранения, поэтому переживает перезагрузку вкладки и исчезает, когда вкладку
закрыли. В `localStorage` на диск в открытом виде не попадает. Та же кнопка в режиме
редактора открывает окно «Редактор» с двумя вкладками — «Фраза клуба» и
«Сохранение» — и ссылкой «Выйти из редактора» под ними.

Регистр и крайние пробелы в фразе не важны. Нет поля `editPass` в
`club.json` — кнопки «Редактор» нет, и правки доступны всем.

Сменить фразу проще всего с самого сайта: кнопка «Редактор» в шапке — в
режиме редактора она открывает окно «Редактор», вкладка «Фраза клуба» (та же
ссылка «Сменить фразу» есть и в окне входа). Нужно
назвать текущую и дважды новую; браузер посчитает SHA-256 и покажет готовую
строку `editPass` для `data/club.json`. В открытой вкладке новая фраза
начинает работать сразу, но насовсем она сменится только после коммита этой
строки — сайт статический и в файлы сам не пишет.

Под вкладками — «Выйти из редактора»: правки снова прячутся, фраза забывается.
Полезно на чужом или общем компьютере.

То же самое из терминала, если сайт под рукой нет:

```bash
node -e 'console.log(require("crypto").createHash("sha256").update("новая фраза").digest("hex"))'
```

Сама фраза нигде не хранится — только хеш. Забудете её — восстановить неоткуда,
придётся вписать в `club.json` новый хеш вручную. Убрать `editPass` из
`club.json` — замка не будет вовсе.

**Это щеколда, а не защита, и важно понимать почему.** Сайт статический: код
открыт, хеш лежит в том же репозитории. Фраза бережёт полку от случайных
нажатий и чужих глаз, но приватности не даёт: страница и данные видны всем,
кто знает адрес. Если полка должна быть только для своих — закрывать надо
весь сайт на уровне хостинга (Cloudflare Access либо Netlify с паролем на
весь стенд), кодом изнутри этого не сделать.

### Сохранение прямо с сайта

По умолчанию правки живут в памяти вкладки, и в репозиторий их переносят
руками. Это можно включить: тогда тот, кто знает фразу, нажимает «Сохранить
на сайт» и коммит уходит сам.

Устроено так: в `data/club.json` появляется блок `publish` с токеном GitHub,
зашифрованным фразой клуба — PBKDF2-SHA-256 (600 000 итераций) выводит из
фразы ключ, им токен шифруется AES-GCM. Расшифровать его может только тот,
кто фразу знает; ни фраза, ни токен никуда не отправляются, наружу уходит
один запрос к `api.github.com`.

```jsonc
"publish": {
  "repo": "владелец/репозиторий",
  "branch": "main",        // необязательно; пусто — ветка по умолчанию
  "salt": "…",             // соль PBKDF2, base64
  "iter": 600000,
  "token": "…"             // iv + шифротекст, base64
}
```

Включается в окне «Редактор» (кнопка в шапке), вкладка **«Сохранение»**:
она просит фразу, репозиторий и токен, проверяет права, шифрует токен прямо
в браузере и отдаёт готовый блок. Делается это однажды и только владельцем —
остальным на эту вкладку заходить незачем. Смена фразы живёт на соседней
вкладке: рядом в одном столбце эти два разговора путали.

**Токену нужны именно права на запись, и это легко упустить.** Репозиторий
публичный, поэтому читать его может любой токен — даже вовсе без доступа к
нему. Отказ приходит только на записи, и выглядит это так, будто сломался
сайт. У fine-grained токена в поле **Repository access** по умолчанию стоит
«Public Repositories (read-only)» — этого мало. Нужно:

* Repository access — **Only select repositories**, и в списке этот репозиторий;
* Permissions → Repository permissions → **Contents: Read and write**.

Поэтому включение сначала читает описание репозитория и смотрит на
`permissions.push`: токен без записи отклоняется сразу и в `club.json` не
попадает. А при сохранении 401 и 403 разведены — «токен неверный или истёк»
и «прав на запись нет» — и к обоим добавляется формулировка самого GitHub. Токен нужен fine-grained, только на этот репозиторий,
с правом **Contents: Read and write**. При смене фразы токен перешифровывается
сам — иначе новая фраза открывала бы замок, но сохранять перестала.

### Чужие правки подтягиваются сами

Правка одной участницы — это коммит, и до пересборки Pages у остальных в
открытых вкладках старая полка. Раньше её приходилось перезагружать, да ещё и
со сбросом кеша: GitHub Pages отдаёт файлы с длинным `max-age`, и обычная
перезагрузка брала их из кеша браузера. Два лекарства:

* `data/*.json` читаются с `cache: 'no-store'` — перезагрузка всегда даёт
  свежее;
* `assets/js/live.js` раз в минуту (и при возврате к вкладке) перечитывает
  `data/books.json` и, если он изменился, обновляет полку на месте, коротко
  поясняя строчкой внизу, почему она поменялась.

Три оговорки, без которых это ломало бы больше, чем чинит, и все три
проверены: незакоммиченные правки неприкосновенны — пока в этой вкладке есть
несохранённое или открыт редактор, опрос молчит; после своего коммита Pages
ещё минуту отдаёт старый файл, поэтому вкладка ждёт ровно тот текст, который
сама отправила, а всё прежнее игнорирует (иначе только что добавленная книга
исчезала бы с полки); в скрытой вкладке опрос не идёт вовсе.

Кода сайта это не касается: `index.html`, стили и скрипты браузер тоже
кеширует, и после выкладки новой версии их подхватит не сразу.

### Как уходит сохранение

Отдельной кнопки «сохранить ещё раз» нет: добавление, правка и удаление книги
уходят коммитом сами. Полоса внизу страницы — отчёт о происходящем
(«уходят в репозиторий…» → «сохранено»), кнопка на ней появляется только
чтобы повторить после неудачи. Сохраняются файлы целиком: `data/books.json`
из текущего состояния вкладки и `data/club.json`, если менялась фраза или
настройки. После коммита GitHub Pages пересобирает сайт за минуту-полторы.

Для участницы это выглядит так: открыла сайт, нажала «Редактор», ввела фразу
(одно поле), добавила книгу — и всё. Токен она не видит и не вводит: его
однажды настраивает владелец репозитория, дальше он лежит в `club.json`
зашифрованным.

**Чем за это платим.** Зашифрованный токен лежит в открытом репозитории,
значит фраза становится настоящим паролем и подбирать её можно офлайн, не
упираясь ни в какие ограничения. Короткая человеческая фраза для этого не
годится — нужна длинная и случайная, слов из пяти. Худшее, что даёт утечка
токена, — испорченный этот самый репозиторий: он откатывается из истории, а
токен отзывается в настройках GitHub. Если такой размен не нравится, честная
альтернатива — вынести токен на сторону: крошечная функция (Cloudflare Worker
или Netlify Function) проверяет фразу и коммитит сама, а в браузер токен не
попадает вовсе.

В предпросмотре артефакта Claude сохранение не работает: песочница не
выпускает запросы наружу. Проверять надо на самом сайте.

Проверка фразы идёт через `crypto.subtle`, а он доступен только по https или
на `localhost`. По `file://` замок не работает и честно об этом пишет.

## Правка карточки

Кнопка **«Внести изменения»** на линии заголовка «Оценки клуба» превращает
эту же страницу в форму: слева обложка и поля книги (название, автор, год, объём, жанр,
издание, ISBN, дата обсуждения, кто предложил), справа — карточка каждого
участника.

Баллы ставятся кликом: критерий, под ним ряд кружков 1…10. Повторный клик по
выбранной цифре снимает оценку. Средний балл участника пересчитывается прямо
в форме, пока вы кликаете, — вводить его негде и незачем. Ниже — «Перечитаешь?»
(да / нет, тоже переключаются повторным нажатием), впечатление и строчка,
забранная с собой.

Тот же элемент используется и в форме добавления книги — он живёт в
`assets/js/ui.js` (`scorePickerHTML`, `wirePickers`, `readPicked`), так что
оба места ведут себя одинаково.

Кнопка **«Удалить книгу»** в панели редактора убирает книгу с полки — с
подтверждением. Как и правки, удаление живёт только в памяти вкладки: чтобы
книга не вернулась после перезагрузки, её элемент нужно удалить из
`data/books.json` (в подтверждении показан нужный `id`).

Сохранение работает как и у новой книги: сайт статический и в файлы не пишет,
поэтому «Сохранить» правит книгу в памяти вкладки и вешает на карточку
плашку «изменено» с кнопкой «Показать JSON для вставки». Скопируйте объект
и замените им соответствующий элемент массива в `data/books.json`.
Уход со страницы с несохранёнными правками спрашивает подтверждение;
«Отменить» возвращает карточку в режим чтения, ничего не записав.

## Виджеты на карточке книги

Пять критериев и три-четыре человека — данных мало, поэтому всё нарисовано
руками в inline-SVG (`assets/js/charts.js`), без библиотек:

* **Шкала среднего балла** — полукруг с засечками и заливкой от персикового
  к бордовому, крупное число в центре, под ним метка «спорная» /
  «единогласно» и строчка о том, насколько разошлись оценки.
* **Профиль книги** — радар-пятиугольник: залитая фигура это средние оценки
  клуба, тонкие контуры — каждый участник. Форма читается быстрее, чем пять
  отдельных чисел: перекос виден сразу. Подписи осей берутся из поля `short`
  у критерия в `club.json` (полные названия на осях не помещаются).
* **Кольцо «Перечитаешь?»** — доля ответивших «да», под ним имена.
* **Место на полке** — какая эта книга по средней оценке среди всех
  прочитанных, и полоска из засечек (по одной на книгу): видно не только
  номер, но и насколько книга оторвалась от соседей по списку.
* **Карточки участников** — средний балл, метка «перечитает» и пять
  мини-шкал по критериям в цвете участника. Цвета аватарок пастельные, для
  полос они притемняются примесью чернил (`color-mix`), иначе заливка
  теряется на кремовом фоне.

Всё считается из тех же `scores`, что и раньше, и подхватывает изменения в
`criteria` автоматически — добавите критерий, радар станет шестиугольником.

## Объёмное наведение на обложку

Крупная обложка — на странице книги и в блоке «Книга года» — поворачивается
вслед за курсором: контейнер задаёт перспективу, внутренний слой крутится по
двум осям пропорционально отклонению курсора от центра и чуть подаётся
вперёд, а сверху ползёт блик. Блик здесь не украшение: без него поворот
плоской картинки почти не читается.

Пока курсор внутри, переход короткий (`.12s linear`) — иначе обложка тянется
за мышью с заметным опозданием; на выходе длинный, чтобы она мягко вернулась.
Код — `assets/js/tilt.js`: `tiltWrap()` даёт разметку, `mountTilt()` вешает
слежение. На тач-экранах и при `prefers-reduced-motion: reduce` эффект
выключается.

## Оформление

* Дисплейный шрифт — **Instrument Serif** (только начертание 400 — вес
  не варьируется, это часть его характера), текст и интерфейс — **Inter**.
* Тёплая светлая палитра: кремовая бумага, глубокий бордовый акцент вместо
  прежнего золота. Все цвета и размеры — переменные в начале
  `assets/css/style.css` (`--void`, `--ink`, `--gold` и т. д. — имена
  остались прежними, поменялись только значения). Цвета обложек живут
  в данных, а не в CSS: `--bg`, `--fg` и `--acc` подставляются из поля
  `art` каждой книги — сами обложки остаются тёмными и разноцветными,
  как настоящие книги на светлой полке.
* Формы везде мягкие: скруглённые карточки, поля и кнопки вместо прежних
  прямых углов.
* Иконки — инлайн-SVG в стиле **Tabler Icons** (24×24, обводка 1.5),
  лежат в `assets/js/icons.js`; заменить на файлы из tabler.io/icons можно,
  подставив другие `<path>` в тот же словарь.
* Поверх страницы — слой зерна (`.grain`), это SVG-шум, а не картинка.
* Все анимации выключаются при `prefers-reduced-motion: reduce`.
* Фавиконка — `assets/favicon.svg`: оранжевый квадрат, раскрытая книга и по
  две строки текста с боков («между строк»).

## Полка: нахлёст вместо скролла

На полке всегда ровно семь книг лицом (`FACE_OUT` в `assets/js/shelf.js`)
и до пяти следующих — стопкой (`PILE_MAX`); всё, что не поместилось сверх
этого, просто не показывается — ни на полке, ни в стопке. Ряд обложек
при этом никогда не скроллится по горизонтали: вместо этого он подгоняется
под фактическую ширину экрана нахлёстом — небольшим, если места хватает,
и заметно плотнее (книги «внахлёст», почти корешок к обложке), если нет.
Это осознанный выбор в пользу простоты и предсказуемой раскладки, а не
попытка бесконечно вместить растущую библиотеку — если книг в клубе
станет больше 12, часть просто не попадёт на полку; найти их всё ещё
можно через поиск и фильтр по жанру (они действуют на всю полку, а не
только на то, что показано).

Ряд, плитка «добавить книгу» и стопка всегда стоят в одну строку и никогда
не переносятся. Стопка ужимается по ширине вместе с полкой, длинные названия
в ней уходят в многоточие. Проверено на ширинах от 360 до 1600 px: семь книг
лицом, пять в стопке, горизонтальной прокрутки страницы нет.

Кнопка «разложить» выкладывает на полку всю библиотеку. Ряд при этом
по-прежнему помещается целиком: книгам разрешён более плотный нахлёст
(`OVERLAP_MAX_OPEN` вместо `OVERLAP_MAX`), а размер обложки пересчитывается
под фактическое число книг. Прокрутки у ряда нет вообще — раньше она была,
и вместе с ней вертикальная обрезка, из-за которой разложенные книги
срезались сверху и снизу.

### Размер книги считается по высоте экрана

Главная задумана как одна страница без вертикальной прокрутки, поэтому
`--cover-w` не формула в CSS, а посчитанное значение: `refitShelf()` в
`assets/js/shelf.js` смотрит, сколько высоты осталось полке после шапки,
героя, панели и подвала, и делает книгу ровно такой, чтобы всё уложилось
в экран. Вторым проходом ширина ограничивается ещё и рядом: если семи
книгам не хватает места вбок, высоту недобираем.

`clamp(96px, min(15.5vw, 25vh), 232px)` в CSS остаётся как значение до
первого расчёта, чтобы первый кадр не мигал. Герой, панель и подвал при
этом ужимаются на невысоких экранах (все вертикальные отступы завязаны на
`vh`) — освободившееся место достаётся полке.

Две тонкости для будущих правок:

* Ширину обложки `fitFrontRow()` измеряет через `offsetWidth` самой книги,
  а не читает `--cover-w`: значение пользовательской переменной приходит из
  `getComputedStyle` неразрешённым, `clamp(...)` так и останется строкой.
* У героя, панели и полки горизонтальные `margin: auto`, а они отключают
  растягивание флекс-элемента по поперечной оси. Поэтому у прямых детей
  `#view-shelf` явно проставлена `width: 100%` — без неё блок ужимается до
  min-content и вылезает за экран.

### Панель над полкой

Первая строка — поиск, сортировка и «Добавить книгу» (только в режиме
редактора);
вторая — чипы жанров. Прокручиваться позволено только полосе жанров: видно
несколько чипов, край последнего уходит под мягкую маску справа, остальные
докручиваются вбок. На узких экранах у сортировки пропадает ведущая иконка,
у «Добавить книгу» — подпись, а поиск сворачивается в иконку и
разворачивается обратно по фокусу.

### Планка и тени

Планка полки идёт в разметке следующим элементом после ряда книг, а
наклонённая книга ближним краем выходит ниже своей коробки — поэтому линия
рисовалась прямо поверх обложек. У `.shelf` есть `z-index`, который поднимает
книги над планкой. Тени две: общая под планкой лёгкая и идёт во всю ширину
страницы (гаснет маской только у самых краёв, чтобы не было видно обрыва),
а объём держит контактная тень каждой книги (`.slot::after`) — она живёт
вместе с книгой и расплывается, когда та поднимается при наведении.

### Наклон и наведение

В покое книга развёрнута корешком к зрителю на `--tilt` (30° по умолчанию).
При наведении разворачивается лицом (`rotateY(0)`) и приподнимается **только
она**; соседи слева и справа лишь чуть приподнимаются, сохраняя тот же угол —
разворачивается всегда ровно одна книга.

Два неочевидных места:

* `perspective` стоит на `.slot`, а не на ряде. Перспектива действует только
  на прямых детей, а между рядом и `.book3d` стоит слот — на ряде наклон
  выродился бы в простое сжатие обложки по горизонтали вместо разворота.
* Сам слот при этом остаётся плоским (никакого `transform-style: preserve-3d`),
  а z-index висит на `.slot`, а не на `.book3d`. Иначе соседние книги делят
  одну 3D-сцену, браузер сортирует их по фактической геометрической глубине
  вместо z-index, и наведённая книга не может подняться поверх соседей.
